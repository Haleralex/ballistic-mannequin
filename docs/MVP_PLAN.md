# MVP: первые пользователи и первые A/B-тесты

Цель MVP — не «сделать всё», а за 2–3 недели узнать три вещи:

1. **Кому это нужно.** Актёрам, режиссёрам и каскадёрам, аниматорам и геймдеву или писателям?
2. **Что их цепляет.** Сам симулятор, возможность поделиться реакцией или будущая репетиционная комната.
3. **Готовы ли платить и за что.**

Всё, что не помогает ответить на эти вопросы, в MVP не входит.

## Гипотезы

| # | Гипотеза | Как проверяем | Сигнал «да» |
|---|----------|---------------|-------------|
| H1 | Реакцией хотят делиться: ссылка или видео — это и есть канал роста | Доля сессий с «Поделиться» или «Скачать клип»; переходы по чужим ссылкам | ≥ 8 % активных сессий делятся; ≥ 20 % открывших ссылку делают свой выстрел |
| H2 | Сильнее всего цепляет одна аудитория, и её видно по тому, какой заголовок лучше конвертирует | A/B лендинга с тремя позиционированиями | Одна версия даёт активацию выше остальных с запасом вне шума |
| H3 | Живая репетиционная комната нужна настолько, что за неё оставляют почту или жмут «оплатить» | Ложная дверь (фича ещё не сделана) и лист ожидания | ≥ 5 % активированных оставляют почту |
| H4 | Есть готовность платить за видео в HD и комнату | Ложная дверь с ценой, два уровня цены | Клик «Оформить» ≥ 2 % при любой цене; разница между ценами |

**Активация** = за сессию сделано ≥ 3 выстрела и досмотрена хотя бы одна реакция ≥ 10 с.

## Что входит в MVP

### 1. Детерминированный повтор (основа для всего остального)
- Все 23 вызова `Math.random()` в симуляции заменяются на генератор с зерном (например, mulberry32). Визуальные эффекты (пыль, капли) могут остаться на обычном `Math.random`, если они не влияют на физику и сценарий.
- Выстрел и смена настроек (оружие, импульс, режим реакции, ускорение кровопотери) записываются как событие с номером шага физики, а не с реальным временем.
- Сценарий от Claude недетерминирован, поэтому в кейс пишется готовый список шагов, а не запрос.
- Формат кейса v1 (`jsonb`, около 1 КБ):
  ```json
  { "v": 1, "seed": 123456, "build": "<git sha>",
    "events": [ { "step": 214, "type": "shot", "weapon": "9mm", "origin": [..], "dir": [..] },
                { "step": 0, "type": "setting", "key": "react", "value": "flee" },
                { "step": 216, "type": "script", "beats": [..] } ] }
  ```
- Хеш состояния (позиции и повороты 14 тел, округлённые) раз в 120 шагов. Тест: один кейс, прогнанный дважды, даёт одинаковые хеши. Кросс-браузерный детерминизм (V8 и SpiderMonkey, разные `Math.sin`) не гарантирован. В MVP проверяем только Chromium, в Firefox меряем расхождение и записываем.

### 2. Поделиться реакцией
- Кнопка «Поделиться» сохраняет кейс на сервер и даёт ссылку `/r/<id>`.
- Страница по ссылке проигрывает реакцию с начала. Там же есть «Повторить», «Перемотать» и «Сделать свой выстрел» — это переход в обычный режим, и именно его мы меряем.
- Превью для мессенджеров (Open Graph): заголовок «Ранение печени из пистолета — реакция за 60 с» и картинка. В MVP картинка — один статичный кадр на тип ранения, без рендер-фермы.

### 3. Скачать клип
- Запись прямо в браузере: `canvas.captureStream()` → `MediaRecorder` → WebM. В Chrome можно сразу MP4, если поддерживается. Сервер не нужен.
- Длительность до 20 с, с водяным знаком и адресом сайта. Водяной знак — это и есть канал привлечения.

### 4. Оценка реалистичности
- После реакции ненавязчивое «Похоже на правду? 👍 / 👎» и необязательный комментарий.
- Пишется в Postgres с id сценария. Это и обратная связь, и данные для будущего взвешивания библиотеки.

### 5. Ложные двери
- Кнопка «Репетиционная комната — смотреть вместе с командой». По клику описание фичи, «Скоро» и поле почты.
- Кнопка «Pro: HD-видео без водяного знака и комната». По клику цена (вариант A/B), «Оформить», потом «Мы ещё не запустились — оставьте почту, дадим скидку».
- Честно: никаких списаний, только интерес и почта.

### 6. Лендинг
- Одна страница перед симулятором: заголовок, клип 5–10 с, кнопка «Попробовать».
- Три варианта позиционирования (тест T1, см. ниже).
- Языки: русский и английский. Сообщества для привлечения в основном англоязычные.

### 7. События, A/B и аналитика (Go + Postgres)
- Анонимный id посетителя в `localStorage`, без cookie и без личных данных. Почта есть только в листе ожидания, с явным согласием.
- Сервер выдаёт вариант эксперимента и запоминает его за посетителем: один посетитель — один вариант навсегда.
- События пачками раз в 5 с и при закрытии вкладки (`sendBeacon`).
- Анализ — SQL-представления: воронка по вариантам, конверсия и доверительный интервал (z-тест двух пропорций). Дашборд — одна простая страница `/admin` за паролем из `.env`.

## Чего нет в MVP

Репетиционная комната (только ложная дверь), рендер-ферма, аккаунты, оплата, мобильные приложения, своя библиотека сценариев от пользователей. Всё это строится после того, как тесты покажут, что нужно.

## Первые A/B-тесты

Трафик на старте маленький, поэтому одновременно идёт не больше двух тестов и только на частых метриках. Порядок величины: чтобы заметить рост 10 % → 15 %, нужно около 700 посетителей на вариант; 20 % → 30 % — около 300.

| Тест | Варианты | Главная метрика | Что решаем |
|------|----------|-----------------|------------|
| **T1 Позиционирование** | A «Для актёров и режиссёров: как тело реагирует на ранение» · B «Для аниматоров и геймдева: реакции на попадание с физикой» · C «Для писателей и сценаристов: что на самом деле происходит после выстрела» | Активация | Для кого делать продукт и где искать пользователей |
| **T2 Первый запуск** | A пустая песочница · B подсказка «Кликните по груди» и готовый первый выстрел | Активация | Нужен ли онбординг |
| **T3 Предложение поделиться** | A кнопки только в панели · B после реакции всплывает «Сохранить этот момент: ссылка или клип» | Доля сессий с share/export | Растёт ли виральность от подсказки |
| **T4 Цена** (после T1) | A 5 $/мес · B 15 $/мес | Клик «Оформить» | Порог цены |

## Метрики и события

`visit`, `landing_cta`, `sim_ready`, `shot` (оружие, зона, тип), `reaction_watched_10s`, `share_link`, `share_open`, `share_convert` (свой выстрел после чужой ссылки), `clip_export`, `rate` (±1, сценарий), `fake_door_open` (room/pro), `fake_door_click` (цена), `waitlist_submit`, `return_d1`, `return_d7`.

## Привлечение первых пользователей

- **Платную рекламу почти наверняка не пропустят.** У Google и Meta строгие правила про оружие и насилие. Ставка на органику:
  - r/Filmmakers, r/acting, r/animation, r/gamedev, r/writing — с подачей «справочник для работы», а не «стреляй в человечка»;
  - школы актёров и каскадёров, сообщества stunt-координаторов;
  - русскоязычные телеграм-каналы про кино, анимацию и геймдев.
- **Контент:** 10–15 коротких клипов «как на самом деле реагирует тело на ранение в бедро / печень / навылет» с водяным знаком, ссылкой и пояснением из сценария.
- **Риск модерации:** везде позиционирование «учебное и справочное». Есть переключатель «без крови» и предупреждение на лендинге.

## Архитектура MVP

```
браузер (статика: лендинг + симулятор, ES-модули)
   │  REST /api/*
   ▼
Caddy (TLS, статика, прокси) ── Go API (net/http, pgx) ── Postgres 16
```

- Один VPS (Hetzner CX22 или аналог, ~5 €/мес), `docker compose`: caddy, api, postgres.
- Бэкап: `pg_dump` по systemd-таймеру в S3-совместимое хранилище.
- CI на GitHub Actions: `go test`, тест детерминизма в headless Chromium, сборка образа.

### Таблицы Postgres

```sql
cases(id text pk, created_at, build text, seed bigint, kind text, zone text, data jsonb, views int)
visitors(id uuid pk, first_seen, lang text, referrer text, utm jsonb)
experiments(key text pk, variants text[], weights int[], active bool)
assignments(visitor_id, experiment_key, variant, assigned_at, pk(visitor_id, experiment_key))
events(id bigserial, visitor_id, session_id, name text, props jsonb, at timestamptz)  -- партиционирование по месяцу позже
ratings(id, visitor_id, case_id null, scenario_id text, value smallint, comment text, at)
waitlist(email citext unique, visitor_id, source text, price_variant text, at)
```

### API

```
POST /api/assign            {visitor, experiments[]}  → {key: variant}
POST /api/events            [{name, props, at, session}]  (пачка, ≤ 100)
POST /api/cases             case v1 → {id}
GET  /api/cases/{id}        → case v1
POST /api/ratings           {scenario, case?, value, comment?}
POST /api/waitlist          {email, source, price_variant?}
GET  /admin/...             воронки по экспериментам (basic auth)
GET  /r/{id}                HTML-обёртка с Open Graph → симулятор в режиме повтора
```

## Разделение на команды агентов

Сначала я фиксирую контракты: формат кейса v1, OpenAPI, схему БД и список событий. Это интерфейс между командами, и после этого они работают параллельно.

| Команда | Что делает | Готово, когда |
|---------|-----------|---------------|
| **0. Подготовка** (я, последовательно) | Разбить `index.html` (2 650 строк) на ES-модули: `sim/`, `render/`, `ui/`; контракты в `docs/` | Симулятор работает как раньше, тесты зелёные, контракты описаны |
| **A. Детерминизм** | Генератор с зерном, журнал событий, повтор кейса, хеш состояния | Тест: 20 кейсов × 2 прогона, хеши совпадают на каждом шаге |
| **B. Бэкенд** | Go API, миграции, тесты на настоящем Postgres, `/r/{id}` с Open Graph, `/admin` | `go test ./...` зелёный, интеграционный тест через docker compose |
| **C. Рост** | Лендинг (RU/EN, 3 варианта), A/B-клиент, события, «Поделиться», запись клипа, оценка, ложные двери, лист ожидания | Сквозной тест: визит → вариант → выстрел → поделиться → открыть ссылку → свой выстрел; события в БД |
| **D. Инфраструктура** | `docker-compose`, Caddyfile, деплой на VPS, бэкапы, CI | `docker compose up` поднимает всё локально; деплой одной командой |
| **Интеграция** (я) | Сборка, ревью, сквозные тесты, запуск | Чек-лист запуска ниже пройден |

Зависимости: 0 → (A, B, D параллельно) → C (нужны A и B) → интеграция.

# HTTP API v1

Go service, JSON over HTTPS. Owner: team B. Consumer: team C. Base path `/api/v1`. All bodies are JSON (UTF-8),
`Content-Type: application/json`. Times are RFC 3339 UTC.

## Common

- **Visitor id**: UUID v4 generated by the browser and kept in `localStorage` (`mq_vid`). Sent in bodies as
  `visitor_id`. Not personal data; there are no accounts.
- **Session id**: UUID v4 per tab, renewed after 30 min of inactivity (`sessionStorage` `mq_sid`).
- **Errors**: `{ "error": "<code>", "message": "<Russian text for the user>" }` with status 400 (malformed),
  404, 413 (too large), 422 (fails validation), 429 (rate limited), 500.
- **Rate limits** per IP (token bucket): events 60 req/min, cases 20/min, waitlist and ratings 10/min, others 120/min.
- **CORS**: origins from `ALLOWED_ORIGINS` (comma-separated). Same-origin deployment needs none.
- **Body size**: 64 KB except `/events` (256 KB).

## Endpoints

### `POST /api/v1/assign`
Sticky experiment variants for a visitor. Unknown or inactive experiments are left out of the answer.
```json
→ { "visitor_id": "…", "experiments": ["t1_positioning", "t2_onboarding"] }
← 200 { "assignments": { "t1_positioning": "b", "t2_onboarding": "a" } }
```
Assignment: weighted by `experiments.weights`, decided by `hash(visitor_id + key)` so it is reproducible, stored in
`assignments` on first request; later requests return the stored variant even if weights change.
First contact also upserts `visitors` (with `referrer` and `utm` if sent: `{ "referrer": "…", "utm": {…} }`).

### `POST /api/v1/events`
```json
→ { "visitor_id": "…", "session_id": "…", "events": [ { "name": "shot", "at": "2026-10-18T12:00:00Z", "props": { … } } ] }
← 202 { "accepted": 12, "rejected": 0 }
```
At most 100 events. Names must be in the taxonomy (`events.md`); unknown names are counted in `rejected`, not stored.
`at` more than 24 h off the server clock is replaced by the server time. Also accepts `navigator.sendBeacon`
(`Content-Type: text/plain` with the same JSON).

### `POST /api/v1/cases`
```json
→ { "visitor_id": "…", "case": { case v1 } }
← 201 { "id": "a7F3kQ9x", "url": "/r/a7F3kQ9x" }
```
Validates against `case-v1.md`. Id: 8 characters base62, random.

### `GET /api/v1/cases/{id}`
`← 200 { case v1 }` · `404`. Counts a view (not blocking the response).

### `POST /api/v1/ratings`
```json
→ { "visitor_id": "…", "scenario_id": "abd-04", "case_id": null, "value": 1, "comment": "на 12 с встал — так не бывает" }
← 201 {}
```
`value` is `1` or `-1`; `comment` at most 500 characters. One rating per visitor and scenario per day (later ones update it).

### `POST /api/v1/waitlist`
```json
→ { "visitor_id": "…", "email": "a@b.ru", "source": "room", "price_variant": "b", "consent": true }
← 201 {}   (also 201 when the address is already there: the answer never reveals whether it was)
```
`consent` must be `true` (152-ФЗ). Email checked for shape only; lower-cased.

### `GET /r/{id}`
HTML for link previews: Open Graph `og:title`, `og:description`, `og:image` (a static image per `meta.kind`) and a
redirect to `/?case={id}`. 404 page if the case does not exist.

### `GET /healthz`
`200 ok` when the database answers.

### Admin (`/admin`, HTTP basic auth from `ADMIN_USER` / `ADMIN_PASSWORD`)
- `GET /admin` — one HTML page: experiments, per-variant funnel, conversion with 95 % interval, p-value vs variant `a`.
- `GET /admin/api/experiments/{key}?metric=activation` — the same as JSON:
  `{ "key": "…", "metric": "activation", "variants": [ { "variant": "a", "visitors": 512, "converted": 61, "rate": 0.119, "ci": [0.093, 0.150] } ], "vs_a": { "b": { "diff": 0.021, "p": 0.18 } } }`
- `GET /admin/api/waitlist.csv`.
